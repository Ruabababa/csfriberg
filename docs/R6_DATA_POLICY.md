# R6 选手数据与赛事统计口径

本文档是 Rainbow Six Siege 选手竞猜的数据规则。固定 81 人种子、数据库导入、后台编辑和游戏判定都必须遵循这里的口径。应用运行期间不请求外部数据 API。

## 赛事范围

只统计以下两类赛事：

1. Six Invitational（简称 SI，包含历史赛事名称变体）。
2. Rainbow Six Major（包含历史上使用的 Six Major 等名称变体）。

区域联赛、挑战者联赛、DreamHack、Gamers8、世界杯和其他第三方赛事不计入这两个统计字段。固定种子中的赛事分类和唯一 ID 已在导入前审核。

## 选手资格

选手必须满足以下条件才进入竞猜数据库：

- 在 Liquipedia 的 R6 选手目录或选手页面中被识别为选手，而不是纯教练、分析师或管理人员。
- 至少在一场 Major 或 SI 的选手阵容/比赛记录中出现。
- 仅出现在队伍介绍、工作人员列表或新闻报道中的人员不算参赛选手。
- 仅注册但没有进入赛事选手阵容或比赛记录的替补，不计入出场数。

## 冠军数和出场数

### Major+SI 出场数

按选手参加过的唯一赛事页面计数：

```text
major_si_appearances = unique(Major 赛事 ID ∪ SI 赛事 ID)
```

同一赛事的预选赛、阶段页、重命名页面不得重复计数。选手在同一赛事代表不同队伍时仍只计一次。

### Major+SI 冠军数

按选手随冠军队伍赢得的唯一 Major/SI 主赛事计数：

```text
major_si_championships = unique(冠军 Major 赛事 ID ∪ 冠军 SI 赛事 ID)
```

只统计主赛事冠军，不统计地区赛冠军、阶段冠军或赛事 MVP。冠军归属必须能从 Liquipedia 的赛事结果和选手阵容交叉确认。

## 位置标准化

选手页面的原始位置必须保留，同时生成用于竞猜比较的标准化位置集合。推荐标准标签如下：

- `Entry`
- `Fragger`
- `Flex`
- `Support`
- `Hard Breach`
- `Soft Breach`
- `IGL`
- `Roamer`
- `Anchor`
- `Lurker`

常见别名应归一化，例如 `Entry Fragger` → `Entry`、`Hard Support` → `Support`、`In-Game Leader` → `IGL`。一个选手可以拥有多个标签，位置比较采用集合交集：完全相同为绿色，存在交集为黄色，无交集为灰色。

纯 `Coach`、`Analyst`、`Manager` 和其他工作人员身份不作为选手位置；如果页面同时记录了选手时期和教练时期，应以参赛时的选手身份为准，并保留当前身份供 `is_active` 判断。

## 其他字段

- 国家/地区：保留 Liquipedia 原始值，再映射到应用内国家代码。
- 赛区：使用赛事体系中的顶层赛区，不使用某一支队伍的临时注册赛区。
- 队伍：默认使用当前队伍；退役选手使用 Liquipedia 标注的最后一支职业队伍。
- 年龄：由出生日期和数据快照日期计算，数据库应保存出生日期和快照时间。
- 现役状态：根据 Liquipedia 当前职业状态和最近队伍信息判断，无法确认时标记为待审核，不自动猜测。

## 数据质量要求

导入前必须检查：

- 稳定来源 ID 唯一且非空；昵称非空但允许重名。
- 出场数、冠军数为非负整数，冠军数不大于出场数。
- 每个符合资格的选手至少有一个 Major/SI 赛事 ID。
- 赛事 ID 去重后再统计。
- 原始页面 URL、来源更新时间、数据版本和解析警告完整保存。
- 解析不确定的记录进入人工复核列表，不直接进入正式竞猜池。
